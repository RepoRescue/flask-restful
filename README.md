# flask-restful (RepoRescue rescue)

A DRF-style REST framework for Flask — declare `Resource` subclasses, mount them on
a Flask app via `Api`, parse request bodies with `reqparse.RequestParser`. This is
a fork of [`flask-restful/flask-restful`](https://github.com/flask-restful/flask-restful)
upstream (last released 0.3.10, archived).

**Modernized for Flask 3.x / Werkzeug 3.x / Python 3.13.**

The upstream project is no longer maintained and the released wheel breaks on a
modern stack: `reqparse.Argument.source` reads `request.json` / `request.values`
via `getattr`, and on Werkzeug 3.x those attribute reads raise `BadRequest`
(an `HTTPException`) on missing or malformed bodies, which used to bubble out as
a 500. This rescue patches that surface so the parser falls back cleanly and
returns a normal 4xx via reqparse's own validation.

## Install

```bash
pip install git+https://github.com/RepoRescue/flask-restful.git
```

Verified against `Flask==3.1.x`, `Werkzeug==3.1.x`, `Python 3.13`.

## Quick start

```python
from flask import Flask
from flask_restful import Api, Resource, reqparse

TODOS = {"1": {"task": "buy milk"}}

class Todo(Resource):
    def get(self, todo_id):
        return TODOS.get(todo_id) or ({"error": "not found"}, 404)

    def post(self, todo_id):
        p = reqparse.RequestParser()
        p.add_argument("task", type=str, required=True, location="json")
        args = p.parse_args()
        TODOS[todo_id] = {"task": args["task"]}
        return TODOS[todo_id], 201

app = Flask(__name__)
Api(app).add_resource(Todo, "/todos/<string:todo_id>")

if __name__ == "__main__":
    app.run(port=5000)
```

End-to-end check (real HTTP, not `app.test_client()`):

```bash
curl -s http://127.0.0.1:5000/todos/1
# {"task": "buy milk"}
curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"task":"ship paper"}' http://127.0.0.1:5000/todos/2
# {"task": "ship paper"}
```

## What was fixed

- `flask_restful/reqparse.py` — `Argument.source(request)` now wraps every
  `getattr(request, "json" / "values" / ...)` call in
  `try/except werkzeug.exceptions.HTTPException`, returning an empty
  `MultiDict()` on failure. This is the load-bearing fix for Werkzeug 3.x,
  where reading the body of a malformed/missing-JSON request raises
  `BadRequest` from inside `getattr`.
- Required-argument errors (e.g. missing `task` on POST with no body) now
  surface as a clean reqparse-generated 400 instead of a 500.
- Drop-in for existing `flask_restful` users on the happy path; the public
  API of `Api`, `Resource`, `RequestParser`, `inputs` is unchanged.

## Known behavior difference (rescue caveat)

The `try/except` around `getattr` is over-broad: any `HTTPException` raised
while reading the request body — including the `BadRequest` Werkzeug raises
for **malformed JSON** — is swallowed and treated as "no body". On the original
flask-restful 0.3.10 + Werkzeug 2.x stack, posting `{not` with
`Content-Type: application/json` to an endpoint without required args would
return `400 Bad Request` from Werkzeug. On this rescue it returns `200` with
the parsed args set to `null`.

This is a regression introduced by the rescue patch, not by the upstream
0.3.10 source. Required-arg validation (the common case) still works because
reqparse re-checks `required=True` after the fallback — so `POST` with empty
or malformed body to an endpoint that declares a required arg still produces
a clean `400`. Endpoints with no required args silently accept malformed
bodies as empty.

If your service relies on Werkzeug surfacing 400 for malformed JSON before
reqparse runs, validate the body explicitly (e.g. `request.get_json(force=False)`
in a `before_request` hook) instead of relying on this fork.

Full evidence trail: see `.reporescue/REPORT.md` (REPORT.md in this repo's
RepoRescue artifacts) — it includes the 8-attack bug-hunt log that confirmed
no 500s leak and the soft finding above.

## Downstream cascade

Verified that [`flask-restful-swagger-3`](https://pypi.org/project/flask-restful-swagger-3/)
runs unchanged on this rescue: its `Api` subclass and `Resource` reuse this
fork's `reqparse` internals, `GET /api/swagger.json` returns a valid OpenAPI
document, and resources serve real HTTP over `werkzeug.serving.make_server`.
A small reproducer lives at `artifacts/flask-restful/downstream_validate.py`
in the RepoRescue tree.
